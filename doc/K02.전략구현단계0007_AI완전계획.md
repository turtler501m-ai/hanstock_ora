# 전략 구현 단계 0007: AI 완전 거래 계획

## 단계 목표

AI가 단순 후보 점수가 아니라 진입, 무효화, 하드 스톱, 목표가, 추적 손절,
시간 청산을 포함하는 완전한 `TradeIntent`를 생성하고, 보유 중에는 최초 투자
논리와 현재 포지션을 함께 보면서 지속적으로 재판단하게 한다.

## 구현 결과

- `PlannerProvider` 프로토콜로 모델 공급자와 전략 어댑터를 분리했다.
- `OpenAIResponsesPlanner`는 Responses API와 strict Structured Outputs를
  사용한다.
- 모든 객체의 필수 필드와 `additionalProperties=false`를 선언한 거래 의도
  JSON Schema를 제공한다.
- 응답 완료 여부, 명시적 refusal, 출력 존재 여부 및 JSON 형태를 검사한다.
- 기존 온라인 접근 차단 설정과 토큰 사용량 저장 방식을 재사용한다.
- `AutonomousAIAdapter.scan`은 시장 컨텍스트의 각 후보에 대해 완전한 의도를
  생성한다.
- `manage_position`은 최초 thesis, 무효화 조건, 이전 결정, 포지션 상태,
  시장 및 포트폴리오 스냅샷을 모델 입력에 포함한다.
- 응답을 도메인 `TradeIntent`로 변환한 뒤 기존 엄격 검증을 다시 수행한다.
- 전략 ID, 버전, 프로필 해시, 시장, 포지션 ID 및 종목을 신뢰 경계에서 다시
  대조한다.

## 실패 및 fallback 정책

다음 상황은 `PlannerError` 또는 검증 예외로 종료되며 거래 의도를 반환하지 않는다.

1. API 키나 모델 누락
2. 온라인 접근 차단
3. HTTP/API 오류 또는 미완료 응답
4. 모델 refusal
5. 누락·비JSON·파싱 불가 응답
6. 전략/시장/포지션 신원 불일치
7. 손절·가격·시간·청산 계획 도메인 검증 실패

규칙 기반 주문이나 이전 AI 결과로 자동 대체하지 않는다. 따라서 모델 장애가
신규 위험 증가 거래로 변환되지 않는다.

## 공식 API 설계 근거

OpenAI 공식 Structured Outputs 지침에 따라 Responses API의 `text.format`에
`json_schema`, `strict=true`를 사용했다. 스키마 준수는 출력 형태를 보장하지만
거래 의미의 안전성을 보장하지 않으므로 애플리케이션 도메인 검증과 결정론적
리스크 게이트를 별도로 유지한다.

## 실행 경계와 검증 상태

이 단계는 시장 데이터나 OpenAI API를 실제 호출하지 않았고 배포하지 않았다.
테스트는 공급자와 HTTP 응답을 mock하도록 작성했으며 사용자 요청에 따라 실행은
최종 검증 단계로 유보했다.
