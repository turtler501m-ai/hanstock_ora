
• # 한스톡 AI 완전 전략 운영 설계 분석

한스톡을 “AI가 완전한 전략을 운영하는 시스템”으로 발전시키려면 AI의 역할을 후보 점수 보정에서 다음 전체 생명주기로 확장해야 합니다.

시장 인식
→ 종목 선정
→ 진입 판단
→ 포지션 크기 결정
→ 주문 방식 결정
→ 보유 상태 재평가
→ 추가매수·축소·손절·익절
→ 체결 확인
→ 전략 성과 평가
→ 전략 중단 또는 개선

다만 완전 자율 운영이 “AI가 원하는 주문을 바로 제출한다”는 뜻이면 위험합니다. 권장 구조는 다음과 같습니다.

> AI는 매매 의도와 전략 판단을 생성하고, 결정론적 리스크 엔진이 허용 범위와 주문 수량을 강제하며, 실행 엔진이 실제 주문과 체결을 관리한다.

# 2. 권장 아키텍처

## 2.1 전략 엔진

모든 전략이 동일한 인터페이스를 구현하게 만드는 것이 첫 단계입니다.

class StrategyEngine(Protocol):
def analyze_market(self, context) -> MarketRegime:
...

      def scan(self, context) -> list[Candidate]:
          ...

      def decide_entry(
          self,
          candidate: Candidate,
          portfolio: PortfolioState,
      ) -> TradeIntent:
          ...

      def manage_position(
          self,
          position: StrategyPosition,
          context: MarketContext,
      ) -> TradeIntent:
          ...

      def on_fill(self, fill: FillEvent) -> None:
          ...

      def review(self, performance: StrategyPerformance) -> StrategyReview:
          ...

AI 전략, 규칙 전략, 하이킨아시 전략, 급락 반등 전략 모두 이 인터페이스를 따르게 합니다.

기존 src/strategy/seven_split.py:200에 후보 계산·AI 평가·배분·보유 신호가 한꺼번에 들어 있는데, 이를 다음처럼 분리하는 것이 좋습니다.

# 4. 시장 국면 판단 계층

AI가 종목만 보고 거래하면 시장 전체 급락이나 변동성 확대에 취약합니다. 모든 전략 실행 전에 MarketRegime을 계산해야 합니다.

예시 국면:

BULL_TREND
BULL_PULLBACK
SIDEWAYS_LOW_VOL
SIDEWAYS_HIGH_VOL
BEAR_RALLY
BEAR_TREND
CRASH
UNKNOWN

입력 데이터:

- KOSPI/KOSDAQ 또는 S&P 500 추세
- 지수 SMA20·60·200
- 시장 폭: 상승 종목 비율
- 변동성 지수
- 거래대금
- 환율
- 금리·선물 변화
- 갭 및 장중 변동성
- 데이터 신선도

전략은 지원하는 국면을 선언합니다.

{
"allowed_regimes": [
"BULL_TREND",
"BULL_PULLBACK",
"SIDEWAYS_LOW_VOL"
],
"blocked_regimes": [
"CRASH",
"BEAR_TREND",
"UNKNOWN"
]
}

AI가 강한 매수를 추천해도 전략의 허용 국면이 아니면 리스크 엔진이 거부해야 합니다.

# 5. 진입 설계

완전한 AI 전략은 “이 종목이 좋아 보인다”가 아니라 다음 항목을 모두 제시해야 합니다.

- 진입 방향
- 진입 가격 범위
- 주문 방식
- 판단 유효기간
- 무효화 가격
- 무효화 조건
- 예상 보유기간
- 이익 목표
- 위험 대비 기대수익
- 추가매수 가능 여부
- 전략 신뢰도
- 사용 데이터 시점

## 진입 허용 공식

AI 판단 이후 결정론적으로 검사합니다.

진입 허용 =
전략 활성
AND 전략 승인 완료
AND 시장 국면 허용
AND 데이터 최신
AND 신뢰도 기준 통과
AND 손절가 존재
AND 손절가 < 진입가
AND 기대수익 / 예상손실 ≥ 최소 R:R
AND 일일 손실 한도 미도달
AND 종목·섹터·시장 비중 제한 통과
AND 중복 포지션 정책 통과
AND 주문 유효기간 미경과

추천 기본 최소 손익비는 전략 성격에 따라 다르게 적용합니다.

- 스캘핑: 1.3R 이상
- 스윙: 1.8R 이상
- 추세 추종: 고정 목표보다 추적손절 사용
- 급락 반등: 1.5R 이상 + 엄격한 시간청산

# 6. 포지션 크기 결정

AI가 직접 “100주 매수”를 결정하게 해서는 안 됩니다. AI는 신뢰도와 손절 계획을 제시하고, 수량은 리스크 엔진이 계산해야 합니다.

현재 src/ai_stock/execution_plan_service.py:22에 이미 기초적인 손절거리 기반 계산이 있습니다.

주당 위험 = 진입가 - 손절가
거래 위험예산 = 운영자금 × 거래당 최대 위험률
위험 기준 수량 = 거래 위험예산 / 주당 위험

최종 수량은 다음 중 최솟값입니다.

최종 수량 = min(
위험 기준 수량,
현금 기준 수량,
단일 종목 비중 기준 수량,
시장별 비중 기준 수량,
섹터 비중 기준 수량,
유동성 기준 수량
)

예시:

운영자금       1,000만 원
거래당 위험률  0.8%
위험예산       8만 원
진입가         50,000원
손절가         48,000원
주당 위험      2,000원

위험 기준 수량 = 80,000 / 2,000 = 40주

AI 신뢰도를 수량에 반영하려면 직접 곱하기보다는 제한된 등급을 쓰는 편이 안전합니다.

신뢰도 0.60~0.69 → 위험예산의 50%
신뢰도 0.70~0.79 → 위험예산의 75%
신뢰도 0.80 이상 → 위험예산의 100%

AI 신뢰도가 아무리 높아도 최대 위험예산을 초과할 수 없어야 합니다.

# 7. 보유 포지션 재평가

완전한 전략 운영에서 가장 중요한 부분입니다. 모든 활성 포지션을 일정 주기로 재평가해야 합니다.

def manage_position(position, context) -> TradeIntent:
...

재평가 입력:

- 최초 진입 논리
- 현재 가격과 수익률
- 평균단가
- 보유기간
- 최초·현재 손절가
- 목표가 도달 여부
- 시장 국면 변화
- 최신 기술지표
- 관련 뉴스 및 이벤트
- 체결되지 않은 주문
- 현재 계좌 위험
- 이전 AI 결정

AI에는 최초 판단을 반드시 함께 제공해야 합니다. 그렇지 않으면 매 주기마다 완전히 새로운 해석을 만들어 판단이 흔들릴 수 있습니다.

## 청산 우선순위

청산은 다음 순서로 처리하는 것이 안전합니다.

1. 브로커 또는 시스템 강제청산
2. 하드 스톱
3. 계좌·전략 위험 한도
4. 데이터·모델 이상에 따른 보호 조치
5. 전략 무효화 조건
6. 최대 보유기간
7. 목표가 분할청산
8. 추적손절
9. AI 재평가에 따른 축소·청산
10. 유지

하드 스톱과 계좌 위험 한도는 AI보다 우선해야 합니다.

# 8. 손절·익절 설계

## 하드 스톱

주문 체결 직후 손절 계획을 활성화해야 합니다.

가능하면 증권사 조건부 주문을 사용하고, 지원되지 않으면 서버 감시 방식으로 운용합니다.

하드 스톱은 AI가 취소할 수 없게 해야 합니다. 변경은 손실 확대 방향이 아니라 위험 축소 방향만 허용하는 것이 좋습니다.

허용: 손절가 48,000 → 49,000
금지: 손절가 48,000 → 46,000

## 분할익절

전략별로 계획을 명시합니다.

1R 도달: 25% 축소
2R 도달: 25% 축소
3R 또는 추세 약화: 25% 축소
나머지: 추적손절

## 시간청산

특히 급락 반등과 이벤트 전략에 필요합니다.

예상 기간 내 반등이 없으면 손익과 관계없이 청산

예:

- 급락 반등: 3~7거래일
- 이슈 순환: 모멘텀 유지 기간
- 스캘핑: 당일 또는 다음 세션 이전
- 중기 추세: 20~60거래일

## 추가매수

“손실 중이면 물타기”가 아니라 사전에 정의된 조건만 허용해야 합니다.

추가매수 허용 =
최초 투자 논리 유효
AND 계획에 add_rules 존재
AND 총 위험예산 초과 없음
AND 추가 후 평균단가 기준 손절 위험 재계산
AND 추가 횟수 제한 미도달
AND 가격이 사전 정의 구간에 진입

권장 기본값:

- 최대 추가매수 1~2회
- 최초 주문 포함 총 위험예산 고정
- 손절가 하향 금지
- 추가매수 때문에 총 손실 가능액이 증가하지 않도록 수량 조정

# 10. 주문 상태 머신

완전자동 운영에는 주문을 한 번 제출하는 것보다 체결 후 상태를 추적하는 일이 중요합니다.

INTENT_CREATED
→ RISK_APPROVED
→ APPROVAL_QUEUED
→ APPROVED
→ ORDER_SUBMITTED
→ PARTIALLY_FILLED
→ FILLED
→ PROTECTION_ACTIVE
→ EXIT_PENDING
→ CLOSED

예외 상태:

REJECTED
EXPIRED
CANCELED
BROKER_UNKNOWN
RECONCILIATION_REQUIRED

필수 처리:

- 미체결 주문 취소 또는 가격 정정
- 부분체결 수량 반영
- 주문 중복 방지
- 서버 재시작 후 상태 복구
- 증권사 잔고와 내부 포지션 대조
- 매도 수량이 실제 보유량을 넘지 않도록 제한
- 매수 체결 전 매도 보호주문 생성 금지
- 체결 이후 손절 보호 활성화 확인

현재 라우터는 주문 제출과 기록 중심입니다. 장기적으로는 src/strategy/router.py:24를 단순 전송 계층으로 두고 별도 OrderManager가 전체 상태를 관리해야 합니다.

# 14. AI 모델 사용 구조

단일 LLM이 모든 결정을 하는 구조보다 역할을 나누는 편이 좋습니다.

Regime Model
시장 국면 판단
↓
Candidate Model
후보 순위 및 매수 논리

보유 포지션 유지·축소·청산 판단

1. 전략별 포지션 소유권
2. AI가 생성하는 완전한 진입·청산 계획

> AI가 시장과 포지션을 지속적으로 판단하고 완전한 거래 계획을 생성하되, 수량·손실·비중·주문 안전은 절대 우회할 수 없는 결정론적 엔진이 통제하는 자율 전략 플랫폼

입니다.
