# 전략 구현 단계 0004: 지속 판단 오케스트레이터

## 단계 목표

전략의 신규 후보 탐색과 기존 포지션 재평가를 한 사이클에서 수행하고, 검증된
거래 의도만 결정론적 리스크 심사를 거쳐 전략 포지션과 관리 주문으로 기록한다.
이 단계는 브로커 주문을 실행하지 않는다.

## 구현 결과

- `StrategyAdapter` 프로토콜
  - `scan`: 신규 거래 의도를 생성한다.
  - `manage_position`: 전략이 소유한 각 활성 포지션을 매 사이클 재평가한다.
- `MarketContext`, `PortfolioContext`
  - 시장/포트폴리오 스냅샷 식별자와 종목별 신뢰 가능한 `RiskSnapshot`을 전달한다.
- `AutonomousStrategyOrchestrator`
  - 활성 전략 포지션 조회
  - 신규 스캔과 모든 활성 포지션의 지속 판단
  - `TradeIntent` 엄격 검증
  - 원본 전략 결정 감사 기록 저장
  - 결정론적 `RiskEnvelope` 평가
  - 신규 진입의 전략 소유 가상 포지션 생성
  - 승인 수량으로 `intent_created` 관리 주문 생성
  - 리스크 결과·최종 행동·거부 사유를 결정 기록에 연결
- 영속화 보강
  - 결정 키와 관리 주문 키 조회 함수
  - 결정에 리스크 결과, 최종 행동, 포지션 및 주문 식별자를 연결하는 함수
- 멱등성
  - `cycle_key + strategy_id + intent_id` 기반 SHA-256 결정 키
  - 결정 키 기반 관리 주문 키
  - 동일 사이클 재처리 시 포지션과 주문을 중복 생성하지 않는다.

## 실패 폐쇄 원칙

다음 상황에서는 관리 주문을 만들지 않는다.

1. 거래 의도 스키마 오류, 전략 소유권 불일치 또는 시장 불일치
2. 신뢰 가능한 종목별 리스크 스냅샷 누락
3. 리스크 평가 예외 또는 리스크 한도 거부
4. 기존 포지션 행동의 소유 포지션 식별자 누락
5. 포지션 또는 관리 주문 영속화 실패

신규 스캔 어댑터가 실패해도 기존 포지션 재평가는 계속한다. 위험 축소 경로가
신규 후보 탐색 장애에 종속되지 않도록 하기 위함이다.

## 주문 실행 경계

오케스트레이터는 관리 주문을 `intent_created` 상태로만 저장한다. KIS 등 브로커
클라이언트를 import하거나 호출하지 않으며, 제출·정정·취소·체결 반영은 후속
주문 상태 머신과 실행 게이트의 책임이다.

## 검증 상태

정상 신규 진입, 멱등 재처리, 리스크 스냅샷 누락 거부, 활성 포지션 지속 판단을
검증하는 단위 테스트를 작성했다. 사용자 요청에 따라 테스트 실행은 최종 단계로
유보했다.
