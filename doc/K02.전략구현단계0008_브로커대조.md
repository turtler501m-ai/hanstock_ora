# 전략 구현 단계 0008: 브로커 격리와 주문 대조

## 목적

KR/US 브로커 호출을 관리 주문 상태 머신 뒤로 격리하고, 프로세스 재시작이나
응답 유실 뒤에도 브로커 누적 체결과 내부 원장을 멱등적으로 대조한다. 실제
API 호출, 실주문 및 배포는 수행하지 않았다.

## 브로커 어댑터

`broker_adapters.py`에 `KRBrokerGateway`와 `USBrokerGateway`를 추가했다.
기존 증권 API는 생성자에 `submitter`, `canceler`, `query` 함수로 주입하므로
어댑터가 인증정보나 API 클라이언트를 새로 생성하지 않는다.

어댑터는 호출 전 저장소에서 관리 주문을 다시 읽고 다음을 강제한다.

- 제출은 CAS 선점이 끝난 `submitting` 상태만 허용
- 취소는 CAS 선점이 끝난 `cancel_pending` 상태만 허용
- 조회는 미종결 브로커 상태만 허용
- 관리 주문 ID, client key, decision, position, 요청 수량이 전달값과 일치
- 관리 주문 시장과 KR/US 어댑터 시장이 일치
- 취소에는 브로커 주문번호가 존재

따라서 일반 전략 객체나 위조된 dict가 기존 API에 직접 전달되는 실행 경로를
제공하지 않는다. 호출 함수 주입은 애플리케이션 조립 계층에서만 수행한다.

## 브로커 상태 정규화

브로커 조회 결과는 다음 공통 상태로 변환한다.

```text
submitted
partially_filled
filled
canceled
rejected
unknown
```

불명확한 응답은 체결이나 거절로 추측하지 않고 `broker_unknown`으로 격리한다.
브로커 누적 체결이 내부 누적보다 감소하거나 주문 요청량을 초과해도 동일하게
불일치로 격리한다.

## 누적 체결 대조

재시작 후 동일 조회가 반복돼도 다음 차이만 `apply_fill`에 전달한다.

```text
신규 적용 수량 = 브로커 누적 체결수량 - 내부 기체결수량
```

브로커가 누적 평균가격을 주는 경우 신규 체결분 가격은 다음처럼 역산한다.

```text
신규 체결가격 =
  (브로커 누적평균 × 브로커 누적수량
   - 내부 평균 × 내부 기체결수량)
  / 신규 적용 수량
```

따라서 이전 체결을 재적용하거나 서로 다른 체결가격의 내부 평균을 왜곡하지
않는다. `submitting` 상태에서 프로세스가 종료된 뒤 실제 체결이 발견되는
경우도 소유권·잔여수량 검사를 거쳐 복구할 수 있다.

## 재시작 복구

저장소의 `list_unsettled_managed_orders()`는 다음 상태를 조회한다.

- `submitting`
- `submitted`
- `partially_filled`
- `cancel_pending`
- `broker_unknown`

`ManagedOrderReconciler.recover_unsettled()`는 시장별 어댑터로 각 주문을
대조하고 주문별 결과를 반환한다. 한 주문의 조회 오류가 다른 주문 복구를
중단시키지 않으며 오류 주문은 다음 대조 주기에 재시도할 수 있다.

## 검증 코드

`tests/test_autonomy_broker_reconciliation.py`에 다음 fake broker 검증을 작성했다.

- 영속 관리 주문 및 `submitting` 상태가 아닌 직접 제출 차단
- 저장값을 위조한 주문 차단
- 동일 누적 체결을 반복 조회해도 한 번만 반영
- 누적 평균에서 신규 체결분 가격 역산
- `broker_unknown` 주문의 재시작 복구

사용자 지시에 따라 테스트는 작성만 했으며 실행하지 않았다. 실제 브로커
호출 테스트와 배포도 수행하지 않았다.
