# K02. 전략 구현 단계 0009 — 시장국면과 신뢰 스냅샷

작성일: 2026-07-23  
범위: 정량 시장국면 분류, 시장·포트폴리오 snapshot builder 계약, 지속 운영 컨텍스트 생성  
검증 정책: 테스트는 작성했으나 실행하지 않았다. 네트워크 호출과 배포도 수행하지 않았다.

## 1. 단계 목표

AI나 전략이 임의로 시장 상태를 선언하지 못하도록 신선한 정량 지표를 사용하는 결정론적 분류기를 제공한다. 분류에 필요한 값이 없거나 오래됐으면 `unknown`으로 만들고, 지속 운영 컨텍스트에서는 신규 위험을 만들 수 없는 안전 스냅샷 오류로 처리한다.

## 3. 지원 시장국면

`MarketRegime`은 다음 상태를 정의한다.

- `bull`: 단·중·장기 이동평균 정배열, 양의 20일 수익, 양호한 시장 폭, 낮은 변동성
- `bull_pullback`: 장기 상승 구조를 유지하지만 단기 가격·수익률이 조정
- `sideways_low_vol`: 중기 이동평균 근처에서 낮은 상대 변동성
- `sideways_high_vol`: 중기 이동평균 근처지만 높은 상대 변동성
- `bear_rally`: 장기 하락 구조 내부의 단기 반등
- `bear`: 단·중·장기 이동평균 역배열, 음의 20일 수익, 약한 시장 폭
- `crash`: 급격한 단기 손실, 큰 낙폭 또는 손실을 동반한 변동성 급등
- `unknown`: 필수 입력 불량·노후화 또는 어떤 정량 조건에도 신뢰성 있게 속하지 않음

## 4. 필수 정량 입력

`MarketRegimeInput`:

- 시장과 데이터 원천
- `data_as_of`, `evaluated_at`
- 지수 현재값
- SMA20, SMA60, SMA200
- 5일·20일 수익률
- 실현 변동성과 기준 변동성
- 상승 종목 비율 `advance_ratio`
- 20일 낙폭

필수 가격·이동평균·변동성은 유한한 양수여야 한다. 수익률과 낙폭은 유한해야 하며 시장 폭은 0~1 범위여야 한다. 시각은 timezone-aware여야 한다.

기본 최대 데이터 나이는 300초다. 미래 시각이나 기준 초과 데이터는 `unknown`이다.

## 5. 판정 우선순위

정량 조건은 다음 순서로 평가한다.

1. 입력 완전성·유한성·신선도
2. crash
3. bull
4. bull pullback
5. bear
6. bear rally
7. sideways high/low volatility
8. unknown

crash를 추세 국면보다 먼저 평가하므로 장기 이동평균이 아직 상승형인 급락 초기에도 위험 상태를 우선한다.

기본 임계값:

```text
crash 20일 낙폭       <= -12%
crash 5일 수익률      <= -8%
crash 변동성 비율     >= 2.5배이며 5일 수익률 < -4%
고변동성 비율         >= 1.3배
bull 시장 폭          >= 55%
bear 시장 폭          <= 45%
횡보 중기 이격        <= 5%
최대 데이터 나이      300초
```

`RegimeThresholds`는 운영자 소유 설정이며 전략 또는 AI 출력에 포함되지 않는다.

## 6. Snapshot Builder 계약

### `MarketSnapshotBuilder`

```text
build_market_input(market) -> MarketRegimeInput
```

### `PortfolioSnapshotBuilder`

```text
build_portfolio_input(market) -> PortfolioBuildInput
```

`PortfolioBuildInput`은 계좌·시장·원천·기준시각, 현금, 총평가액, 주식평가액, 종목별 `RiskSnapshot`, 전체 보유 payload를 제공한다.

구체적인 KIS/LS/US API 접근은 이 Protocol 밖의 후속 구현이다. 이번 단계는 네트워크를 사용하지 않는다.

## 7. 지속 운영 ContextProvider

`TrustedSnapshotContextProvider`는 8단계 `ContinuousStrategyService`가 요구하는 `ContextProvider`를 구현한다.

### 시장 컨텍스트

1. builder에서 정량 입력 획득
2. 요청 시장과 입력 시장 일치 확인
3. 결정론적 국면 분류
4. `unknown`이면 `SnapshotBuildError`
5. 입력과 판정 사유를 `ai_market_snapshots`에 불변 저장
6. 저장 ID를 가진 `MarketContext` 반환

### 포트폴리오 컨텍스트

1. 동일 시장의 market context가 먼저 생성됐는지 확인
2. 계좌·시장·원천·risk snapshot 존재 확인
3. 평가액의 유한·비음수 검사
4. 포트폴리오 기준시각과 신선도 확인
5. 전략이 제공한 국면을 신뢰하지 않고 분류된 시장국면으로 모든 `RiskSnapshot`을 교체
6. 전체 입력을 `ai_portfolio_snapshots`에 불변 저장
7. 저장 ID를 가진 `PortfolioContext` 반환

시장 또는 포트폴리오 컨텍스트 생성 실패는 8단계 서비스에서 `safety_snapshot_blocked`가 되며 오케스트레이터가 호출되지 않는다.

## 8. 감사 재현성

snapshot key는 다음 입력을 canonical JSON으로 변환한 SHA-256이다.

- 시장/계좌 식별
- 데이터 기준시각
- 전체 정량 또는 포트폴리오 payload

기존 snapshot 저장소는 동일 키·동일 내용 재요청만 멱등 허용하고, 동일 키가 다른 내용을 가리키면 거부한다.

전략 결정의 `market_snapshot_id`, `portfolio_snapshot_id`를 통해 당시 분류 입력과 계좌 위험 입력을 재현할 수 있다.

## 9. 작성한 테스트

`tests/test_autonomy_regime.py`에 다음 검증을 작성했다.

1. bull
2. bull pullback
3. sideways low volatility
4. sideways high volatility
5. bear rally
6. bear
7. crash

## 10. 후속 작업

1. KR/US 지수·시장 폭·변동성 입력 builder 구현
2. 휴장·장전·장후 데이터 신선도 정책 분리
3. 시장별 기준 변동성 산출 및 영속화
4. 포트폴리오 builder를 브로커 대사 결과와 연결
5. 국면 전환의 최소 지속시간 또는 히스테리시스 검토
6. 시장국면별 전략 허용 목록과 lifecycle 정책 연결
7. 최종 단계에서 경계값·노후화·결측·급락 장애주입 테스트 실행

## 11. 단계 결과

시장국면은 이제 전략 설명이나 AI의 자유 텍스트가 아니라 신선한 정량 입력과 고정 임계값으로 판정할 수 있다. 분류 불가 상태는 `unknown`으로 명시되고, 지속 운영 컨텍스트에서 fail-closed된다.

시장·포트폴리오 입력과 분류 결과가 불변 스냅샷으로 저장되므로 이후 전략 결정과 주문의 근거를 재현할 수 있다.
