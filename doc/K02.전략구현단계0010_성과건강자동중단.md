# K02. 전략 구현 단계 0010 — 성과·건강 자동중단

작성일: 2026-07-23  
범위: 자율 전략 건강 집계, 임계 기반 review/suspend, 선택 해제, action-aware lifecycle  
검증 정책: 테스트는 작성했으나 실행하지 않았다. 배포하지 않았다.

## 1. 단계 목표

전략 결정, 관리 주문, 전략 포지션과 하드스톱 보호 원장을 기준으로 전략의 운영 건강을 반복 평가한다. 오류나 안전 불일치가 임계를 넘으면 운영자의 다음 점검을 기다리지 않고 전략을 자동 중단한다.

다만 중단은 신규 위험만 막는다. 기존 포지션의 `REDUCE`, `EXIT`, `CANCEL_PENDING`은 계속 허용해 안전한 청산을 막지 않는다.

## 3. 권위 데이터와 집계

`RepositoryHealthSource`는 메모리 카운터가 아니라 다음 영속 데이터를 집계한다.

### 전략 결정

`ai_strategy_decisions`에서:

- 호출/관찰 수
- `rejection_reason`이 있는 오류 수
- intent metadata의 `fallback_used`
- rejection reason의 상태·버전·프로필 mismatch

### 관리 주문과 fill

`ai_managed_orders`에서:

- `broker_unknown` 수
- `filled` 상태 또는 양의 `filled_qty`가 있는 주문 수

fill은 관리 주문의 누적 체결 수량을 통해 집계한다. 후속 독립 fill 원장이 추가되면 체결 건수·가격 품질 집계를 확장할 수 있다.

### 전략 포지션

`ai_strategy_positions`에서:

- 전략별 누적 실현손익
- 종료 순서의 누적 실현손익 곡선
- 누적 고점 대비 최대 실현 낙폭

### 보호 상태

활성 포지션과 `ai_position_protections`를 결합해:

- 보호 누락
- 보호 상태 비활성
- `protected_qty != remaining_qty`

를 미보호 수로 집계한다.

## 4. 건강 정책

`StrategyHealthPolicy` 기본값:

```text
비율 판단 최소 호출 수       5
최대 오류율                  20%
최대 fallback 비율           50%
허용 상태 mismatch           0
허용 broker_unknown          0
허용 미보호 포지션           0
최대 실현 낙폭               100,000
최대 누적 실현 손실          100,000
```

금액 기준은 운영자 자본과 통화에 맞춰 후속 설정에서 명시적으로 주입해야 한다.

## 5. 중단 수준

### `review_required`

- 최소 표본 이후 오류율 초과
- 최소 표본 이후 fallback 비율 초과
- 실현 낙폭 초과
- 누적 실현 손실 초과

전략 품질 검토가 필요하지만 즉각적인 주문/상태 불일치가 확인되지는 않은 경우다.

### `suspended`

- 전략 상태/버전/소유권 mismatch
- 하나 이상의 `broker_unknown`
- 하나 이상의 미보호 포지션

계좌·주문 안전을 확인할 수 없는 경우이므로 즉시 더 강한 상태로 전환한다.

여러 사유가 동시에 존재하면 `suspended`가 우선한다. 기존 `retired` 또는 `suspended` 상태를 더 약한 `review_required`로 되돌리지 않는다.

## 6. 원자 상태 변경

`strategy_repository.halt_ai_strategy()`은 `BEGIN IMMEDIATE` 트랜잭션에서:

1. 현재 전략 행 조회
2. 기존 상태보다 약하지 않은 목표 상태 결정
3. 상태 변경
4. `selected=0`
5. `autonomy_health_halt` 이벤트와 전체 건강 payload 기록
6. 커밋

을 수행한다.

상태 변경과 선택 해제만 성공하고 이벤트가 누락되거나, 이벤트만 남고 전략이 계속 선택되는 부분 성공을 방지한다.

## 7. 지속 서비스 통합

`ContinuousStrategyService`는 각 전략 사이클 직전에:

```text
health_service.evaluate_and_enforce(strategy_id)
```

를 호출한다.

반환된 `StrategyHealth`는 오케스트레이터의 lifecycle gate에 전달된다. 건강 조회/집행 자체가 예외를 일으키면 정상으로 추정하지 않고 `halt_required=True`와 mismatch 상태를 만들어 신규 위험을 fail-closed한다.

한 전략의 건강 평가 오류는 다음 전략과 다른 시장의 포지션 관리를 막지 않는다.

## 8. Action-aware lifecycle

기존 lifecycle 게이트가 중단 상태의 모든 intent를 거부하면 손절·청산까지 막히는 결함이 생긴다. 이를 액션별로 분리했다.

다음은 상태가 `review_required`, `suspended`, `retired`이거나 health halt가 있어도 허용된다.

- `REDUCE`
- `EXIT`
- `CANCEL_PENDING`

다음 신규 위험 행동은 거부된다.

- `ENTER_LONG`
- `ADD`

전략 카탈로그 조회 실패, 등록 누락, 버전·프로필 mismatch도 위험 감소 액션은 허용한다. 오케스트레이터의 포지션 소유권 및 결정론적 risk envelope가 실제 매도 수량을 전략 소유 잔량 이내로 제한한다.

## 9. 작성한 테스트

### `tests/test_autonomy_health.py`

- 정상 전략 무변경
- 오류율·fallback 초과 시 review
- mismatch·broker unknown·미보호 시 suspend
- 실현 손실·낙폭 초과 시 review
- lifecycle health 변환
- 상태 변경·선택 해제·이벤트의 동일 트랜잭션 결과

### `tests/test_autonomy_lifecycle.py`

- suspended 및 health halt 상태에서도 EXIT 허용

### `tests/test_autonomy_continuous_service.py`

- 각 전략 사이클 직전 건강 평가
- health 결과를 오케스트레이터에 전달

사용자 지시에 따라 테스트는 실행하지 않았다.

## 10. 후속 작업

1. 건강 집계 기간과 최소 표본을 전략 유형별 설정으로 분리
2. 독립 fill 이벤트 원장을 이용한 슬리피지·부분체결 품질 집계
3. 실현 낙폭을 계좌 통화와 초기 위험예산 대비 비율로 정규화
4. 반복되는 모델 timeout, 데이터 품질, 보호 복구시간 지표 추가
5. 운영자 검토 후 `review_required/suspended` 해제 절차와 재승인
6. 건강 상태 대시보드 및 경보 연결
7. 최종 단계에서 상태 경쟁, DB 오류, 중단 중 청산 허용 테스트 실행

## 11. 단계 결과

전략 운영 상태는 이제 단순 누적수익률이 아니라 AI 호출 품질, 상태 일치, 주문 불확실성, 보호 공백, 실현 성과를 함께 반영한다. 안전 불일치는 전략 상태·선택·이벤트를 원자적으로 갱신하며 신규 위험을 자동 중단한다.

중단 상태에서도 기존 포지션의 축소·청산·미체결 취소가 유지되므로 자동중단 자체가 위험 감소를 방해하지 않는다.
