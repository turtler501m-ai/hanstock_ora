# 전략 구현 단계 0011 — 실운영 컨텍스트

## 결과

자율 전략 런타임 앞에 KR/US 공통 읽기 전용 실운영 스냅샷 경계를 추가했다.
브로커 조회, 최신 AI 종목 스캔, 종목 시세, 시장 지수 자료가 모두 신뢰 가능한
경우에만 기존 결정론적 `AutonomyRuntime`으로 데이터를 전달한다.

구현 파일은 `src/strategy/autonomy/operational_context.py`이다.

## 안전 불변조건

- 모듈은 주문 API를 보유하거나 호출하지 않는다.
- 계좌 조회 오류, 합성 잔고, 설정 자본 fallback, 0 이하 평가금액을 거부한다.
- 완료된 동일 전략 스캔이 없거나 스캔·후보·시세가 노후하면 실패한다.
- 종목 시세, 최소 20개 가격 관측치, 유동성, 섹터가 빠지면 실패한다.
- 보유 종목의 종목·섹터 메타데이터가 하나라도 빠지면 전체 스냅샷을 거부한다.
- 계정·시장·거래일별 첫 신뢰 평가금액을 `ai_daily_equity_baselines`에
  `UNIQUE(account_id, market, trading_date)`로 불변 저장한다.
- 첫 기준선 생성 cycle은 warmup으로 신규 위험을 차단한다. 같은 거래일의 다음
  신뢰 cycle부터 `현재 평가금액 - 기준선 - 순외부현금흐름`으로 당일 손익을
  산출한다.
- 입출금은 `ai_daily_account_cashflows`의 대사 완료 행만 보정에 사용한다.
  미대사 현금흐름 또는 외부체결이 있으면 손익을 추정하지 않고 실패한다.
  관측 등록은 `record_daily_account_cashflow()`, 검토 완료 표시는
  `mark_daily_account_cashflow_reconciled()`로 수행하며 금액 자체는 수정하지 않는다.
- `protection_global_block`은 `HardStopProtectionService.global_gate_signal()`의
  실제 미보호 포지션 감사 결과와 warmup 상태의 합으로 결정한다.
- `strategy_exposure_value`는 동일 계정·시장·전략의 활성 가상 포지션 잔여수량과
  최신 시세로 계산한다. `open_position_risk_amount_excluding_reservations`는
  동일 계정·시장의 모든 활성 long 포지션에 대해
  `max(평균단가-현재손절가, 0) × 잔여수량`을 합산한다.
- 활성 포지션의 평단·현재 손절·잔여수량·방향 또는 대응 브로커 보유수량이
  불완전하면 fail-closed한다.
- pending risk reservation은 기존 runtime이 별도로 합산하므로 위 포지션 위험에
  포함하지 않아 이중 계산을 방지한다.
- `kill_switch_active`는 기존 `RiskEngine.check_kill_switch()` 결과를 사용한다.
  파일시스템 또는 엔진 조회 오류는 활성 상태로 간주한다.
- 기본 자동 대사 허용은 주문이 외부 브로커로 나가지 않는 demo 환경에만
  적용된다. real 환경에서는 별도 외부체결 대사 소스를 주입하지 않으면 실패한다.
- 시장 지수 관측치가 200개 미만이거나 국면이 `unknown`이면 실패한다.
- 명시적 `assemble_operational_run_once()` 반환 함수를 호출해야만 한 주기가 실행된다.
- `AUTONOMY_ENABLED`는 기존 런타임 게이트로 남으며 scheduler import/start와 연결하지 않았다.
- run-once 조립은 `AUTONOMY_TRADING_ENV=demo`와 승인 필요 설정을 강제한다.
- 실계좌 주문과 배포는 이 단계에서 수행하지 않는다.

## 데이터 흐름

1. `ai_stock_repository.list_scans()`에서 시장·전략의 최신 완료 스캔을 찾는다.
2. 같은 scan id의 후보만 읽고 데이터 시각을 검증한다.
3. 후보와 활성 전략 포지션 심볼의 시세·가격열을 조회한다.
4. KIS 계좌를 조회하고 오류 또는 synthetic fallback을 거부한다.
5. 지수 추세·수익률·변동성·시장 폭으로 국면을 결정한다.
6. 기존 `build_runtime_contexts()`가 재검증할 account/market snapshot을 만든다.
7. 명시적 run-once 호출 시에만 AI 계획과 결정론적 위험 심사를 수행한다.

## 테스트

`tests/test_autonomy_operational_context.py`에 다음 검증을 작성했다.

- 정상 KR 조회 스냅샷 생성
- 노후 스캔 fail-closed
- 브로커 오류 fail-closed
- demo 및 approval 기본 강제
- 일손익 기준선 최초 warmup 및 다음 cycle 해제
- 입금 보정 당일 손익
- 미대사 현금흐름·외부체결 fail-closed
- 실제 하드스톱 전역 게이트 반영
- 활성 전략 노출 및 예약 제외 개방위험 계산
- 포지션 손절·평단·수량 결측과 브로커 보유 불일치 차단
- 킬 스위치 실제 상태 및 조회 실패 차단

사용자 지시에 따라 이 단계에서는 테스트를 실행하지 않았다. 전체 테스트와 로컬
검증은 최종 구현 단계에서 일괄 수행한다.
