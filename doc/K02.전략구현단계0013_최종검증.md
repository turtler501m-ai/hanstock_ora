# K02 전략 구현 단계 0013: 최종 검증

## 최종 구현 범위

AI가 신규 후보와 모든 활성 전략 포지션을 반복 평가하고 완전한
`TradeIntent`를 생성하는 자율 전략 런타임을 구현했다. AI 의도에는 전략
버전과 프로필 해시, 진입 범위, 주문 형식, 하드스톱, 무효화 조건, 목표,
추적손절, 최대 보유기간 및 축소 비율이 포함된다. AI는 실행 수량을 지정할
수 없다.

결정론적 위험 엔진은 다음 조건을 모두 중앙에서 강제한다.

- 거래당 위험과 계좌 총 오픈 위험
- 현금 버퍼
- 종목·시장·섹터·전략 비중
- 실제 보유 및 미체결 예약 노출
- 유동성 참여율
- 일일 손실과 일일 신규위험 주문 수
- 시장국면과 데이터 신선도
- 킬스위치와 하드스톱 보호 상태
- 전략 소유 가상 포지션 수량

판단, 위험예약, 전략 포지션, 관리 주문, 주문 이벤트, 체결, 하드스톱
보호, 시장·계좌 스냅샷과 일중 평가금액 기준선은 DB에 영속화된다. 승인
직전에는 최신 권위 스냅샷으로 위험을 다시 계산하며 허용 수량이 감소한
경우 주문을 변경하거나 확대하지 않고 거절한다.

## 실행 및 복구

- 관리 주문은 멱등 키와 compare-and-set 상태 전이를 사용한다.
- 제출, 부분체결, 전량체결, 취소, 만료, 거절, 브로커 미확정 상태를
  구분한다.
- 브로커 누적 체결의 증가분만 전략 포지션에 원자 반영한다.
- 체결 키 중복은 DB 유니크 제약으로 차단한다.
- 시작 시 미종결 주문, 브로커 보유량, 전략 가상 포지션 및 보호 주문을
  대조한다.
- 신규 매수 체결은 전체 잔여수량 하드스톱이 확인되기 전 완료 처리되지
  않는다.
- 실거래 보호 주문을 지원하지 않는 브로커 어댑터는 신규 매수 제출을
  fail-closed 차단한다.
- 중단 전략과 킬스위치 상태에서도 `REDUCE`, `EXIT`,
  `CANCEL_PENDING` 위험감소 행동은 허용한다.

## 운영 기본값

자율 운영은 기본 비활성이다. 기본 환경은 demo, 승인 필수, 실거래
비활성이며 실거래에는 자율 운영·전역 실거래·실환경·승인 정책·별도
실거래 opt-in이 모두 필요하다. 프리셋 적용은 전략을 실거래 승인 상태로
자동 승격하지 않는다.

배포와 실주문은 수행하지 않았다.

## 최종 테스트

2026-07-23에 다음 검증을 최종 단계에서 수행했다.

1. `python -m unittest discover -s tests`
   - 624개 테스트
   - 결과: `OK`
2. `powershell -ExecutionPolicy Bypass -File tools\check-encoding.ps1`
   - 결과: `UTF-8 check passed`
3. `powershell -ExecutionPolicy Bypass -File tools\verify-local.ps1`
   - 종료 코드: `0`
   - 내부 테스트: 624개 `OK`
   - UTF-8 검사 통과

검증 과정에서 발견한 다음 문제를 수정한 후 전체 테스트를 반복했다.

- 자율 패키지 최초 import 시 DB 저장소 순환 import
- Windows 임시 SQLite 연결 미종료 테스트
- 동일 사이클의 신규 후보와 포지션 재평가 멱등 판정
- 위험감소 EXIT의 전량 축소 기본 계약
- 기존 스케줄러 승인 테스트의 실제 로컬 DB 상태 간섭

`verify-local.ps1`의 선택 검사에서 현재 개인 `.env`의
`REQUIRE_APPROVAL=false`가 표시됐다. 저장소 기본값과 `.env.example`은
승인 필수이며 자율 런타임도 승인 큐를 우회하지 않는다. 개인 `.env`는
보안 정책에 따라 수정하거나 저장소에 포함하지 않았다.

`git diff --check`는 사용자가 이미 수정 중인
`doc/K01.전략설계분석.md`의 기존 후행 공백을 보고한다. 해당 사용자
문서는 현재 작업 범위에서 변경하거나 정리하지 않았다. 이번에 추가한
자율 전략 코드와 K02 문서에서는 별도 후행 공백 오류가 확인되지 않았다.
