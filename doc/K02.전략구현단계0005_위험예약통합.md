# 전략 구현 단계 0005: 위험예약 통합

## 목적

개별 AI 의도가 동일한 계좌 현금과 위험 한도를 동시에 통과한 뒤 병렬로
초과 주문을 만드는 경쟁 조건을 차단했다. 결정론적 승인 이후 주문 생성 전에
현금과 위험예산을 원자적으로 예약하며, 실패 및 주문 종료 시 예약 생명주기를
정리한다.

## 오케스트레이터 처리 순서

위험을 늘리는 `ENTER_LONG`과 `ADD`의 순서는 다음과 같다.

```text
TradeIntent 검증
→ RiskEnvelope 승인 및 권위 수량 산출
→ 전략 포지션 소유자 확인/생성
→ reserve_risk_budget (BEGIN IMMEDIATE)
→ managed order 생성
→ decision에 최종 결과 연결
```

예약에 전달하는 금액은 임의의 전략 원본값이 아니다.

- 현금: `RiskDecision.estimated_cost`
- 위험: `RiskDecision.risk_amount`(승인 진입가·손절거리·승인 수량의 곱)
- 현금 상한: 해당 종목의 신뢰된 `RiskSnapshot.available_cash`
- 계좌 예약 위험 상한: `RiskDecision.account_risk_reservation_limit`

`RiskLimits.max_risk_per_trade_pct`는 한 주문 한도이고
`RiskLimits.max_total_open_risk_pct`는 계좌 전체 오픈 위험 한도이므로 서로
구분한다. 두 번째 정상 주문이 첫 주문의 거래당 한도 때문에 차단되지 않는다.
저장소는 같은 계좌·시장의 모든 활성 전략 예약 합계를 원자적으로 검사하므로
병렬 전략도 계좌 전체 한도를 중복 사용할 수 없다.

신뢰 스냅샷은
`open_position_risk_amount_excluding_reservations`를 별도 필드로 제공한다.
RiskEnvelope는 다음 값을 권위 있는 예약 총한도로 계산한다.

```text
계좌 예약 위험 상한 =
  총자산 × max_total_open_risk_pct
  - 활성 예약을 제외한 실제 오픈 포지션 위험
```

활성 예약은 저장소가 별도로 합산하므로 스냅샷 필드에 포함하지 않는다. 이를
통해 실제 포지션 위험과 예약 위험의 이중계산을 방지한다. 반대로 해당 필드가
누락되거나 음수·NaN이면 신규 위험 주문은 fail-closed로 거부된다.

청산 주문은 신규 현금·위험을 소비하지 않으므로 예약하지 않는다.

## 실패 정리

- 예약 실패: 의사결정을 거절하고 이번 처리에서 새로 만든 미체결
  `pending_entry` 포지션을 닫는다.
- 주문 생성 실패: 활성 예약을 즉시 해제하고 새 미체결 포지션을 닫은 뒤
  의사결정을 거절한다.
- 포지션 정리는 `filled_qty=0`, `remaining_qty=0`, `pending_entry`인 행에만
  허용해 실제 보유 포지션을 실수로 닫지 않는다.
- 예약 키는 계좌·시장·전략·포지션·주문 조합이며 동일 재처리는 같은 금액일
  때만 멱등적으로 기존 예약을 반환한다.

## 주문 종료 정책

`ManagedOrderService`는 종료 상태 전이 뒤 포지션 소유자의 활성 예약을 찾아
다음과 같이 확정한다.

| 주문 결과 | 예약 결과 |
|---|---|
| 미체결 취소 | `released` |
| 거절 | `released` |
| 만료 | `expired` |
| 전량 체결 | `consumed` |
| 일부 체결 후 취소 | `consumed` |

부분체결 진행 중에는 잔여 주문이 있으므로 예약을 활성 상태로 유지한다.
예약 해제/소비 함수는 멱등적이어서 종료 이벤트 재처리에도 금액이 이중으로
변경되지 않는다.

## 저장소 보강

- `get_active_risk_reservation_for_position()`: 주문 소유 포지션의 활성 예약 조회
- `abandon_pending_strategy_position()`: 미체결 신규 포지션 shell 안전 정리
- 기존 `release_risk_reservation()`: `released`, `expired`, `consumed` 확정에 사용

## 검증 코드

- 기존 오케스트레이터 fake 저장소에 예약 계약을 추가했다.
- 거래당 실제 위험과 계좌 전체 위험 상한이 서로 다른 권위 값으로 전달되는지,
  기존 오픈 위험이 신규 수량·예약 가능액을 줄이는지 검증한다.
- `tests/test_autonomy_risk_reservation_integration.py`에 미체결 취소, 만료,
  일부체결 후 취소의 예약 상태 검증을 작성했다.
- 예약/주문 생성 실패 정리와 예약 없는 청산 경로도 오케스트레이터 계약으로
  검증 가능하게 분리했다.

사용자 지시에 따라 테스트는 실행하지 않았다. 최종 단계에서 전체 검증을
일괄 수행한다.
