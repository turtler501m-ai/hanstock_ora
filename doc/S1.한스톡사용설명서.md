# S1.한스톡사용설명서

## 처음 이 프로젝트를 보는 사용자를 위한 시작 안내

이 프로젝트는 국내주식 자동매매, 해외선물 시그널 검증, AI/QuantConnect 보조 대시보드를 함께 담고 있습니다. 처음 보는 경우에는 바로 실거래를 켜지 말고 아래 순서대로 확인하세요.

### 1. 먼저 무엇을 실행할지 구분합니다

- `한스톡 대시보드`: 국내주식 계좌, 보유종목, 매매 신호, 승인 대기열, 성과를 보는 메인 화면입니다.
- `AI 대시보드`: AI 후보, 리스크, 모델 상태, 주문 흐름을 보는 보조 화면입니다.
- `해외선물 신호 대시보드`: Telegram 해외선물 시그널 수집/파싱/검증/성과를 보는 화면입니다.
- `환경설정`: `.env` 값을 확인하고 수정하는 화면입니다.

일반 사용자는 먼저 `한스톡 대시보드`와 `환경설정`만 보면 됩니다. AI/해외선물/QuantConnect 기능은 필요한 경우에만 확인하세요.

### 2. 로컬 환경을 준비합니다

PowerShell에서 프로젝트 루트(`C:\0.DOC\workspace`)로 이동한 뒤 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
```

그 다음 `.env`에 KIS API 키, 계좌번호, 실행 모드를 입력합니다. 처음에는 반드시 아래 안전값을 유지하세요.

```text
DRY_RUN=true
TRADING_ENV=demo
ENABLE_LIVE_TRADING=false
REQUIRE_APPROVAL=true
```

### 3. 대시보드를 실행합니다

현재 로컬 실행은 아래 스크립트를 사용합니다.

```powershell
powershell -ExecutionPolicy Bypass -File tools\server.ps1 restart
```

브라우저에서 접속합니다.

```text
http://127.0.0.1:8000
```

서버 상태와 로그는 아래 명령으로 봅니다.

```powershell
powershell -ExecutionPolicy Bypass -File tools\server.ps1 status
powershell -ExecutionPolicy Bypass -File tools\server.ps1 logs
```

### 4. 처음 확인할 화면 순서

1. `환경설정`에서 API 키, 계좌번호, `DRY_RUN`, `TRADING_ENV`, `ENABLE_LIVE_TRADING` 값을 확인합니다.
2. `한스톡 대시보드 > 개요`에서 서버와 계좌 조회가 정상인지 봅니다.
3. `보유/리스크`에서 보유종목과 현금 비중을 확인합니다.
4. `신호/계획`에서 매매 신호와 실행 계획이 어떻게 만들어지는지 봅니다.
5. `주문승인`에서 승인 대기 주문이 쌓이는지 확인합니다.
6. 실제 주문 전송이 필요한 경우에도 먼저 `DRY_RUN=true` 상태에서 충분히 검증합니다.

### 5. 테스트로 현재 상태를 확인합니다

변경 전후에는 아래 명령을 실행합니다.

```powershell
python -m unittest discover -s tests
```

대시보드, 거래 로직, 설정, DB, 시그널 파서에 영향을 주는 변경을 했다면 전체 테스트를 돌리는 것을 기본으로 합니다.

### 6. 실거래 전환 전 필수 확인

실거래는 아래 조건이 모두 의도적으로 설정된 경우에만 가능합니다.

```text
DRY_RUN=false
TRADING_ENV=real
ENABLE_LIVE_TRADING=true
```

이 세 값을 동시에 바꾸기 전에는 KIS 계좌, 상품코드, 주문 수량, 승인 정책, Slack 알림, 거래 시간, 손실 한도를 반드시 확인하세요. 프로젝트 기본 운영 원칙은 `DRY_RUN=true`, `REQUIRE_APPROVAL=true`입니다.

### 7. 어디를 수정해야 하는지 빠르게 찾는 법

- 대시보드 화면: `web/templates/`, `web/static/css/`, `web/static/js/`
- FastAPI 라우트: `src/dashboard.py`
- 국내주식 자동매매 엔진: `src/trader.py`, `src/strategy/`
- KIS API: `src/api/`, `src/kis_client.py`
- 해외선물 시그널: `src/futures_signals/`
- 설정: `.env`, `src/config.py`
- 테스트: `tests/`

처음에는 기능을 추가하기보다 화면 실행, 환경설정, 테스트 통과 여부를 먼저 확인하세요.

## Project Analysis

## 프로젝트 목적

`hanstock`은 KIS Open API 기반 국내주식 자동매매와 해외선물 시그널 대시보드를 함께 제공하는 Python/FastAPI 프로젝트입니다. 로컬에서 개발하고 검증한 뒤 GitHub 저장소 `turtler501m-ai/hanstock_ora`에 푸시하고, VM은 같은 저장소를 pull 받아 실행하는 구조로 정리되었습니다.

## 주요 기능

- FastAPI 대시보드: 계좌, 보유종목, 매매 후보, 실행 계획, 승인 대기열, 성과, 리스크 상태 표시
- 국내주식 Seven Split 전략: RSI, SMA, Bollinger Band, MACD, 포트폴리오 비중, 현금 버퍼 기반 주문 계획 생성
- KIS 국내주식 API 연동: 토큰, 잔고, 시세, 일봉, 주문
- KIS 해외선물 API 연동: 해외선물 잔고, 포지션, 주문, 취소, 시세 조회
- Telegram 해외선물 시그널 수집: Telethon 기반 메시지 수집, Claude API 기반 추출, 정규식 fallback
- 해외선물 시그널 검증/실행: 진입가, 손절, 익절, 계약수 파싱, 모의/실거래 실행 상태 관리
- QuantConnect MNQ 연동: 프로젝트 상태, 컴파일, 배포, 주문 API 래핑
- SQLite 기반 런타임 저장소: 거래, 승인, 결정 로그, 시그널 DB
- Slack 알림: 주문 및 오류 알림

## 현재 저장소 기준

- 기준 원격 저장소: `https://github.com/turtler501m-ai/hanstock_ora.git`
- 기준 브랜치: `main`
- 개발 위치: `C:\0.DOC\workspace`
- VM 반영 방식: `git pull origin main` 후 `./scripts/vm/server.sh restart`

## 강점

- 테스트가 넓게 깔려 있습니다. 현재 `python -m unittest discover -s tests` 기준 166개 테스트가 통과합니다.
- 주문 제출에 다중 안전장치가 있습니다. `DRY_RUN`, `TRADING_ENV`, `ENABLE_LIVE_TRADING`, `REQUIRE_APPROVAL`이 함께 작동합니다.
- 대시보드가 운영에 필요한 주요 상태를 한 화면에서 다룹니다.
- 로컬 Windows 실행 스크립트와 VM/Linux 실행 스크립트가 모두 준비되어 있습니다.

## 확인된 리스크

- GitHub Actions 등 일부 기존 운영 파일에 인코딩 깨짐이 남아 있습니다.
- `src/dashboard.py`가 3000줄 이상으로 커져 라우트, 서비스, 환경설정, QuantConnect, 시그널 기능이 한 파일에 섞여 있습니다.
- `.github/workflows/auto_trade.yml`은 일부 한글이 깨져 있고, `database` 브랜치 push 방식도 현재 운영 정책과 재검토가 필요합니다.
- `src/futures_signals/poll.py`에는 기본 Telegram API ID/HASH fallback 값이 코드에 있습니다. 실제 값이면 즉시 제거해야 합니다.
- VM 운영은 새 `scripts/vm` 경로 기준으로 clone 또는 remote 변경 작업이 필요할 수 있습니다.

## Architecture

## 디렉터리 구조

```text
src/
  api/                 KIS, KIS 해외선물, QuantConnect API 클라이언트
  db/                  공통 DB repository
  futures_signals/     해외선물 시그널 수집, 파싱, 저장, 검증, 실행
  notifier/            Slack 알림
  strategy/            Seven Split 전략, 지표, 리스크, 라우팅
  utils/               로깅 유틸
  dashboard.py         FastAPI 대시보드 엔트리포인트
  trader.py            자동매매 엔진 엔트리포인트
  config.py            환경변수 설정

web/
  templates/           Jinja/HTML 화면
  static/              CSS, JavaScript

tests/                 unittest 기반 테스트
tools/                 로컬 검증, 서버, 계좌 점검 도구
config/                Telegram 채널 등 프로젝트 설정
src/integrations/      QuantConnect MNQ paper auto 등 외부 연동 코드
```

## 실행 엔트리포인트

- 대시보드: `src.dashboard:app`
- 트레이더 직접 실행: `python src\trader.py`
- 스케줄러: `src/scheduler.py`
- 해외선물 Telegram poller: `src/futures_signals/poll.py`
- 로컬 서버 스크립트: `scripts/local/server.cmd`, `tools/server.ps1`
- VM 서버 스크립트: `scripts/vm/server.sh`

## 대시보드 흐름

1. `scripts/local/server.cmd` 또는 `scripts/vm/server.sh`가 `uvicorn src.dashboard:app`을 실행합니다.
2. `src/dashboard.py`가 `.env`를 로드하고 FastAPI 앱을 구성합니다.
3. 정적 파일은 `web/static`, 화면은 `web/templates`에서 제공합니다.
4. API 라우트는 KIS, SQLite, 캐시 파일, QuantConnect, Telegram collector 상태를 읽어 화면에 전달합니다.

## 국내주식 자동매매 흐름

1. `src/trader.py`가 설정과 KIS 클라이언트를 초기화합니다.
2. 계좌 잔고와 보유종목을 조회합니다.
3. `src/strategy/seven_split.py`가 보유종목 신호, 매수 후보, 포트폴리오 계획을 계산합니다.
4. 주문은 `DRY_RUN`, `TRADING_ENV`, `ENABLE_LIVE_TRADING`, `REQUIRE_APPROVAL` 조건을 통과해야 합니다.
5. 승인 필요 시 SQLite 승인 대기열에 저장하고, 승인 후 주문을 제출합니다.
6. 거래 결과와 결정 로그는 런타임 DB에 저장합니다.

## 해외선물 시그널 흐름

1. Telegram collector 또는 poller가 채널 메시지를 수집합니다.
2. Claude API 또는 fallback parser가 메시지에서 시그널을 추출합니다.
3. `src/futures_signals/parser.py`가 종목, 방향, 진입가, 손절, 익절, 계약수를 정규화합니다.
4. 시그널은 `.runtime/signals.db`에 저장됩니다.
5. 대시보드에서 검증, 모의 성과, paper/live 실행 상태를 조회합니다.
6. 실행은 `src/futures_signals/executor.py`가 상태 파일과 KIS 해외선물 API를 사용합니다.

## 저장소와 런타임 파일

- Git 추적 대상: `src`, `web`, `tests`, `tools`, 설정 예시, 운영 스크립트
- Git 제외 대상: `.env`, `.runtime`, `logs`, DB, token/session/cache 파일
- 주요 런타임 파일:
  - `.runtime/trades.sqlite`
  - `.runtime/signals.db`
  - `.runtime/balance_snapshot.json`
  - `.runtime/executor_state.json`
  - `.runtime/futures_telegram*`

## Risk and Security

## 실거래 안전장치

실제 주문 제출은 아래 조건을 모두 확인해야 합니다.

```text
DRY_RUN=false
TRADING_ENV=real
ENABLE_LIVE_TRADING=true
```

`REQUIRE_APPROVAL=true`이면 주문은 즉시 제출되지 않고 승인 대기열에 들어갑니다. 대시보드에서 승인해야 주문 처리 단계로 넘어갑니다.

`ONLINE_ACCESS_BLOCKED=true`이면 KIS/LS/Bybit/Telegram/QuantConnect/OpenAI/yfinance/Slack 등 외부 접속과 모든 주문 실행을 차단합니다. 승인 대기 주문은 `pending` 상태로 유지되고, 대시보드는 거래 DB와 마지막 계좌 스냅샷을 계속 표시합니다. 차단 중 새로 수집할 수 없는 정보는 마지막 저장 시각과 stale/offline 상태로 표시될 수 있습니다.

```text
TRADING_ENV=demo
ENABLE_LIVE_TRADING=false
REQUIRE_APPROVAL=true
ONLINE_ACCESS_BLOCKED=false
```

## VM 자동 현행화 및 새 폴더 배포

로컬에서 VM을 최신 상태로 맞출 때는 `scripts/local/deploy-vm.ps1`을 사용합니다. VM 안에서 코드를 직접 수정하지 않고 GitHub의 `main` 브랜치를 기준으로 반영합니다.

```text
host=168.110.102.249
zone=us-central1-b
project=hanstock-server
user=turtler800
ssh key=~/.ssh/id_ed25519
repo=~/hanstock
```

일반 배포:

```powershell
.\scripts\local\deploy-vm.ps1
```

이미 GitHub에 push된 버전을 VM에만 반영:

```powershell
.\scripts\local\deploy-vm.ps1 -SkipPush
```

VM SSH 접속:

```powershell
.\scripts\local\connect-vm.ps1
```


## 스케줄러 분석 및 운영상 유의사항 (Scheduler Precautions)

스케줄러 동작의 신뢰성과 오류 없는 알림 전송을 위해 정립된 유의사항입니다.

### 1. Slack 알림 3,000자 용량 초과 예방 (Chunking)
- **현상**: 세븐 스플릿 스캔 대상이나 매수 후보가 대량으로 도출될 경우, 슬랙 알림 메시지의 전체 텍스트 길이가 3,000자를 초과해 슬랙 서버에서 `HTTP 400: invalid_attachments` 오류로 전송이 거부(유실)될 수 있습니다.
- **예방 조치**: 이를 위해 텍스트 자동 분할(2,800자 기준 청크화) 엔진을 도입하였습니다. 신규 스케줄러 구동 전 최신 코드가 VM에 반영되었는지 반드시 확인하세요.

### 2. AI (PPO) 모델 구동을 위한 디펜던시 주석 해제
- **현상**: 스케줄러 동작 로그에 `[WARN] Failed to load PPO model: No module named 'stable_baselines3'` 경고가 기록되면, 강화학습 가중치 모델 대신 Heuristic 모델로 우회 작동하게 됩니다.
- **예방 조치**: AI 가중치 가이드라인(`ai_strategy_enabled=true`) 기능을 활성화하려면, `requirements.txt` 하단부의 `stable-baselines3`, `gymnasium` 디펜던시 주석을 해제하고 VM 환경에서 패키지를 수동으로 설치(`pip install -r requirements.txt`)해 주어야 합니다.

### 3. 크론 스케줄링의 표준 타임존 규정 (`CRON_TZ`)
- **현상**: GCP VM의 하드웨어/OS 타임존이 UTC로 설정되어 있을 경우, 한국 시장 개장 시간에 스케줄러가 비정상적으로 구동되거나 오작동할 수 있습니다.
- **예방 조치**: VM의 크론탭(`crontab -e`) 설정 시 반드시 최상단에 `CRON_TZ=Asia/Seoul` 지시자를 추가하여, 한국Standard시간 기준 평일 09:00 ~ 15:00 스케줄이 정상적으로 트리거되도록 예방 조치해야 합니다.

## StockCodingDataSample 분석

`StockCodingDataSample/StockCodingDataSample.exe`는 PyInstaller로 패키징된 Python 3.12 기반 독립 실행형 Dash 애플리케이션입니다. 내부 엔트리 모듈명은 `dash_kiwoom_data_saver`이고, 보조 모듈 `utils`에 키움증권 REST TR 래퍼가 들어 있습니다. 실행 파일은 `dash`, `dash_bootstrap_components`, `plotly`, `pandas`, `requests`, `loguru`, `tendo` 등을 포함합니다.

### 1. 샘플의 목적

이 샘플은 자동매매 엔진이라기보다 **키움증권 API에서 국내 주식/지수 차트 데이터를 조회하고 CSV로 저장하는 데이터 수집 도구**에 가깝습니다.

- Dash 웹 UI를 `http://127.0.0.1:8050/`에서 실행합니다.
- API 키와 Secret Key를 받아 키움 OAuth 토큰을 발급합니다.
- 모의투자/실서버를 전환합니다.
- 종목 또는 지수를 선택해 일봉, 주봉, 월봉, 분봉, 틱봉 데이터를 조회합니다.
- 조회 결과를 CSV로 저장하고 Plotly 캔들 차트와 거래량 차트를 표시합니다.
- 중복 실행 방지를 위해 `tendo.singleton`을 사용합니다.

### 2. 화면 구성과 사용자 흐름

주요 화면은 두 카드로 구성됩니다.

- `API 설정`: API 키, 시크릿 키, 모의투자 사용 여부, 설정 저장, 서버 연결 버튼
- `데이터 조회 및 저장`: 종목 검색, 차트 구분, 분/틱 단위, 통합 시세 사용, 수정주가 사용, 최대 요청 개수, 저장 경로, 조회 및 저장 버튼

기본 저장 경로는 `C:/kiwoom_stock_data`입니다. 설정값은 실행 파일 기준 경로의 `data.pkl`에 pickle로 저장되고, 종목 기본정보 캐시는 `stock_basic_info.csv`로 저장됩니다.

### 3. 키움 API 연결 구조

`utils.KiwoomTR` 클래스가 키움 REST 호출을 담당합니다.

인증 흐름:

- `POST /oauth2/token`
- 요청 파라미터: `grant_type=client_credentials`, `appkey`, `secretkey`
- 응답에서 `token`, `expires_dt`를 저장
- 만료 시점 1분 전이면 재로그인

서버 URL:

- 모의투자: `https://mockapi.kiwoom.com`
- 실서버: `https://api.kiwoom.com`
- 모의 WebSocket URL: `wss://mockapi.kiwoom.com:10000/api/dostk/websocket`
- 실 WebSocket URL: `wss://api.kiwoom.com:10000/api/dostk/websocket`

샘플에는 WebSocket URL 설정은 있지만, 분석된 주요 흐름은 REST 차트 조회입니다.

### 5. 데이터 정제 방식

주식 일봉/주봉/월봉 데이터는 키움 원본 필드를 한글 컬럼으로 변환합니다.

- `dt` -> `날짜`
- `open_pric` -> `시가`
- `high_pric` -> `고가`
- `low_pric` -> `저가`
- `cur_prc` -> `종가`
- `trde_qty` -> `거래량`
- `trde_prica` -> `거래대금(백만)`
- `trde_tern_rt` -> `거래회전율`
- `pred_pre_sig_nm` -> `상하한가`

추가 계산 컬럼:

- `전일대비(%)`, `전주대비(%)`, `전월대비(%)`
- 일봉에서는 `상장주식수`가 있으면 `시가총액(억)`을 계산

분봉/틱봉은 `일자`, `시간`, `시가`, `고가`, `저가`, `종가`, `거래량` 중심으로 정리합니다. 가격 필드는 음수 부호가 붙을 수 있어 `abs(int(x))` 형태로 절대값 처리합니다.

### 6. 종목 마스터 수집

보조 모듈은 KRX/LS 계열 공개 마스터 파일도 내려받습니다.

- KOSPI: `https://new.real.download.dws.co.kr/common/master/kospi_code.mst.zip`
- KOSDAQ: `https://new.real.download.dws.co.kr/common/master/kosdaq_code.mst.zip`

다운로드한 `mst` 파일은 `cp949` 기준으로 파싱하며, 거래정지 종목과 우선주를 제외한 보통주 목록을 구성합니다. 샘플은 키움 `ka10099` 결과와 이 상장 리스트를 조합해 `KOSPI 주식`, `KOSDAQ 주식`, `ETF`, `ETN`, `ELW`, `리츠종목`, `뮤추얼펀드` 등으로 구분합니다.

### 7. 차트와 저장 파일

조회 결과는 UTF-8 BOM 포함 CSV(`utf-8-sig`)로 저장합니다. Plotly 차트는 2행 구조입니다.

- 1행: 캔들 차트
- 2행: 거래량 막대
- 이동평균선: 5, 10, 20, 60, 120일
- 템플릿: `plotly_white`

날짜 포맷:

- 일/주/月봉: `%Y%m%d` -> `%Y-%m-%d`
- 분봉: `%Y%m%d%H%M%S` -> `%Y-%m-%d %H:%M`
- 틱봉: `%Y%m%d%H%M%S%f` -> `%Y-%m-%d %H:%M:%S.%f`

### 8. 한스톡에 참고할 부분

한스톡은 현재 KIS 중심 구조이므로 샘플을 그대로 합치는 것은 적절하지 않습니다. 다만 다음 요소는 참고 가치가 있습니다.

- 브로커 API 클라이언트를 `KiwoomTR`처럼 인증, 토큰 갱신, TR 호출, 연속조회 처리로 분리한 점
- `cont-yn`, `next-key` 기반 페이지네이션을 래퍼 메서드 안에 숨긴 점
- 차트 원본 필드를 내부 표준 컬럼으로 변환한 뒤 저장/시각화를 분리한 점
- 종목 마스터를 별도 캐시 파일로 저장하고 검색 옵션을 구성한 점
- 분봉/틱봉/일봉/주봉/월봉 조회 UI를 하나의 공통 흐름으로 묶은 점

한스톡에 이식한다면 우선순위는 다음이 적절합니다.

1. `src/api/`에 키움 클라이언트를 별도 모듈로 추가하고 KIS 클라이언트와 직접 섞지 않습니다.
2. 차트 데이터 표준 컬럼을 `날짜`, `시가`, `고가`, `저가`, `종가`, `거래량` 또는 영문 내부 스키마로 통일합니다.
3. CSV 저장보다 한스톡의 DB/캐시 계층으로 저장 경로를 연결합니다.
4. 대시보드에는 “데이터 수집/검증” 보조 화면으로 붙이고, 매매 실행 로직과는 분리합니다.
5. 실서버 호출은 기존 안전 기본값(`DRY_RUN=true`, `ENABLE_LIVE_TRADING=false`)과 별도 승인 흐름을 유지한 뒤 연결합니다.

### 9. 주의사항

- 샘플은 바이너리 패키지라 원본 소스가 직접 제공된 상태는 아닙니다. 위 내용은 PyInstaller 아카이브의 코드 객체, 함수명, 문자열 상수 분석을 바탕으로 정리한 것입니다.
- API 키와 Secret Key를 pickle 파일에 저장하는 구조는 운영 보안에 취약합니다. 한스톡에 반영할 때는 `.env` 또는 별도 secret 저장소를 사용해야 합니다.
- 샘플의 WebSocket URL은 설정에 존재하지만, 실시간 체결/호가 수신 로직까지 확인된 것은 아닙니다.
- 키움 API를 실제로 호출하려면 키움증권 REST API 권한과 정확한 TR 명세 확인이 필요합니다.

## AI스톡 (AI 주도 종목 분석·자동매매)

AI스톡은 한스톡(국내)·미스톡(미국)·내러티브 데이터를 결합해 AI가 시황·종목 선정·매매 타이밍을 주도하는 독립 메인 메뉴입니다. 진입 경로는 `/ai-stock`이며, 구현 계획은 `docPlan/11.AI스톡_구현계획.md`에 있습니다.

### 개요와 한계

- AI는 시황 해석·종목 선정·타이밍을 **주도**하지만, 자금·수량·실거래 허용은 항상 결정적 안전 계층(RiskEngine·정책·`automation_level`)이 게이팅합니다.
- AI는 미래 목표가격·수익률을 확정 제시하지 않습니다. `confidence`는 모델 신뢰 수준이며 **상승확률이 아닙니다**.
- AI 실패·저신뢰·차단 시 룰 기반으로 자동 강등되어 시스템이 멈추지 않습니다.

### 세부 탭 (9개)

시장 브리핑 · 내러티브 · AI 종목 발굴 · 종목 분석 · 관찰종목 · 포트폴리오 · 성과 검증 · AI 전략 관리 · 실행 계획. 상단 공통 필터에서 시장(전체/한국/미국), 분석 기준일, 전략, 점수 임계를 조정합니다.

### AI한스톡(KR) / AI미스톡(US) 구분

- 통화(KRW/USD), 종목코드(6자리/티커), 지수, 데이터 공급자(KIS/미스톡), DB가 시장별로 분리됩니다. 두 계열 데이터를 직접 합산하지 않으며, 포트폴리오 환산 시에만 환율·기준시각을 함께 표기합니다.

### 점수 산식과 내러티브

- `base = 룰·기술·모멘텀·내러티브·AI` 가중합, `final = clamp(base × 국면승수 × 데이터품질승수 − 위험감점, 0, 100)`.
- 룰 최소 점수 미달 후보는 AI가 승격하지 못하고, AI confidence 미달·fallback 시 AI 가중치를 0으로 재정규화합니다. 모든 가중치·임계는 환경설정/전략 profile/정책에서 변경 가능합니다(하드코딩 금지).

### 종목 유니버스 (ETF 포함·소형주 제외)

- ETF를 포함(태깅)하고, 시총·거래대금·가격 하한 미달 소형주와 관리·정지·우선주·스팩·신규상장을 제외합니다. 기준 수치는 정책에서 시장별로 변경합니다.

### 1차 배치 / 2차 실시간

- 1차(일/주 배치): 유니버스 + 시황 파일을 컨텍스트로 종목을 점수화·선정합니다.
- 2차(장중 실시간): 1차 후보 풀에 대해서만 진입/청산 타이밍 신호를 생성합니다(KR 실시간, US 폴링). 신호가 곧 주문이 아니며 정책·리스크 게이트를 통과해야 합니다.

### 시황 브리핑 파일과 데이터 신선도

- 월/주/일 시황을 `.runtime/ai_stock/briefings/{market}/`에 JSON+MD로 저장하고 점수화 컨텍스트로 재사용합니다. TTL을 초과한 stale 데이터는 confirmed·실행 계획·자동 타이밍에 사용하지 못하고 화면에 배너로 표시됩니다.

### 관찰종목 상태

`discovered → watching → confirmed → execution_planned` (또는 rejected/expired). **AI 단독으로 confirmed가 되지 못하며**, 결정적 검증(점수·룰·위험·신선도·진입가)을 통과해야 합니다.

### 자동화 레벨(0~6)과 demo→live 전환

- `automation_level` 0(분석만)~6(주문 자동). 기본 정책은 Level 4(실행 계획까지만 자동)입니다.
- 자동 승인(5)·자동 주문(6)은 전략별 정책과 리스크 한도, 안전 가드(`DRY_RUN=false`+`ENABLE_LIVE_TRADING=true`+전략 `approved`+페이퍼 검증)가 모두 열려야만 허용되며, **기존 시장별 승인·주문 경로로만** 수행합니다(브로커 직접 우회 없음).
- 운영은 데모(`TRADING_ENV=demo`)로 먼저 검증한 뒤 실계좌로 단계 전환합니다. 스케줄 자동 실행은 `dispatch_due_schedules()`가 AI스톡 전용 자동화 엔진을 호출하며, 주문 생성 경로(`run_scheduled_cycle`)를 타지 않습니다.

### 실행 계획 연결 조건

confirmed 상태 · 승인된 전략 · fresh 데이터 · 진입가·`stop_price` 존재 · `risk_per_share>0` · 리스크/비중/일일손실 한도 통과 · 중복 없음. 수량은 RiskEngine 규칙(`risk_budget / risk_per_share`)으로 계산하며, 손절가가 없으면 계획을 생성하지 않습니다.
